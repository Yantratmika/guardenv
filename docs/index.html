Your .env secrets,
safe inside Git.

guardenv encrypts your .env files into guarded.env files that you commit with the rest of your code, and puts the plain .env back automatically after every clone and pull. One project, one repository, no separate secrets folder to chase.

What it does

01

Encrypts on commit

A pre-commit hook encrypts every tracked .env with AES-256-GCM into guarded.env and stages it. Plaintext never reaches Git.

02

Restores on pull

post-checkout and post-merge hooks decrypt guarded.env back to .env, so your app just works after git clone or git pull.

03

Keeps .env ignored

guardenv init makes sure .env files are in .gitignore, finds every one in your repo (monorepos included), and writes the config.

04

Key stays off the repo

The key lives in ~/.guardenv/<name>, with a unique name per project, so work for two different teams never clashes.

Quick start

cd your-project
guardenv init          # find .env files, create key, install git hooks
git add -A
git commit -m "Add guardenv"   # guarded.env is encrypted and committed for you

For a teammate: clone the repository, save the shared key to ~/.guardenv/<secret-name> (the name is in .guardenv/config), then run: 

guardenv install-hooks
guardenv decrypt       # .env files appear

After that, everything is automatic. See exactly what happens at each step.

Install

Windows (Scoop)

scoop bucket add guardenv https://github.com/yantratmika/scoop-guardenv
scoop install guardenv

New to Scoop? irm get.scoop.sh | iex in PowerShell installs it in one minute, with no admin rights.

Any OS

Download the archive for your platform from the Releases page, extract it, and put guardenv on your PATH. With Go installed you can also run: 

go install github.com/yantratmika/guardenv@latest

Windows note: the binary is not code-signed. Scoop installs normally run without a prompt; a manual browser download may show a SmartScreen warning (More info, then Run anyway).

Good to know

  • Anyone with the key can read the secrets. Share it over a secure channel, and treat it like a password.
  • If you lose the key, the encrypted files cannot be recovered. Keep a backup in your password manager.
  • guardenv keeps small teams' project secrets convenient. It is not a replacement for a production secrets manager. Read the limits.
